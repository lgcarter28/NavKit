\chapter{Exact Schedules and ECI Plant Integration}

\section{Multi-Rate Contract}

Physics, Autopilot, and Guidance use independent exact rational schedules with
the bandwidth ordering
\begin{equation}
f_{\mathrm{phys}}
\geq
f_{\mathrm{ap}}
\geq
f_{\mathrm{guid}}.
\label{eq:trajectory_rate_order}
\end{equation}
The selected rates must be integer compatible with the application master
cadence, and the application must visit every producer deadline exactly.
Schedule epochs are generated from a rational rate and integer sample index,
not by repeatedly adding a binary floating-point period.

Guidance and Autopilot outputs are zero-order held between their respective
due epochs. The Vehicle response and ECI plant advance at every Physics epoch.
Diagnostic rows recorded between producer epochs contain the currently held
command, not a recomputed or linearly interpolated command. Stepwise command
traces are therefore expected and preserve the exact producer cadence.
The IMU and strapdown schedules are independent consumers: every published IMU
increment still reaches Navigator, while Autopilot receives those same
increments through the moving window in
\cref{eq:imu_moving_average_rate}. A lower-rate aided navigation state may be
the selected controller-facing source without slowing the high-rate plant.

\section{Attitude}

The body inertial angular rate is trapezoidally accumulated over an interval:
\begin{equation}
\Delta\boldsymbol{\theta}_{ib,k}^{b}
=
\frac{1}{2}
\left(
\boldsymbol{\omega}_{ib,k-1}^{b}
+
\boldsymbol{\omega}_{ib,k}^{b}
\right)\Delta t_k.
\label{eq:trajectory_delta_theta}
\end{equation}
The incremental quaternion is generated by the rotation-vector exponential
map,
\begin{equation}
\delta\quat_k
=
\begin{cases}
\left[
\cos\!\left(\frac{\theta_k}{2}\right),\,
\dfrac{\sin(\theta_k/2)}{\theta_k}
\Delta\boldsymbol{\theta}_{ib,k}^{b}
\right],
& \theta_k=\norm{\Delta\boldsymbol{\theta}_{ib,k}^{b}}>0,\\[6pt]
\left[1,\,\dfrac{1}{2}\Delta\boldsymbol{\theta}_{ib,k}^{b}\right],
& \theta_k\rightarrow 0.
\end{cases}
\label{eq:trajectory_delta_quaternion}
\end{equation}
With the implemented right-side body increment,
\begin{equation}
\quat_{b,k}^{i}
=
\operatorname{normalize}_{q_w\geq0}
\left(
\quat_{b,k-1}^{i}\otimes\delta\quat_k
\right).
\label{eq:trajectory_quaternion_integration}
\end{equation}

\section{Translation Options}

All translational integration is performed on Cartesian ECI
$\{\pb^{i},\vb^{i},\ab^{i}\}$.

\subsection{Semi-Implicit Euler}

The \texttt{semi\_implicit\_euler} option uses current realized acceleration:
\begin{align}
\vb_k^{i}
&=\vb_{k-1}^{i}+\ab_k^{i}\Delta t_k,
\label{eq:semi_implicit_velocity}\\
\pb_k^{i}
&=\pb_{k-1}^{i}+\vb_k^{i}\Delta t_k.
\label{eq:semi_implicit_position}
\end{align}

\subsection{Trapezoidal Predictor-Corrector}

The default \texttt{trapezoidal\_predictor\_corrector} option uses
\begin{align}
\vb_k^{i}
&=
\vb_{k-1}^{i}
+
\frac{1}{2}
\left(
\ab_{k-1}^{i}+\ab_k^{i}
\right)\Delta t_k,
\label{eq:trapezoidal_velocity}\\
\pb_k^{i}
&=
\pb_{k-1}^{i}
+
\frac{1}{2}
\left(
\vb_{k-1}^{i}+\vb_k^{i}
\right)\Delta t_k.
\label{eq:trapezoidal_position}
\end{align}

Before evaluating endpoint gravity, the implementation predicts position with
\begin{equation}
\pb_{k,\mathrm{pred}}^{i}
=
\pb_{k-1}^{i}
+
\vb_{k-1}^{i}\Delta t_k
+
\frac{1}{2}\ab_{k-1}^{i}\Delta t_k^2.
\label{eq:endpoint_position_predictor}
\end{equation}
The predicted position is transformed to ECEF, gravity is evaluated there and
rotated to ECI, and \cref{eq:force_to_realized_acceleration} is reevaluated using the
updated attitude and realized specific force. The resulting $\ab_k^{i}$ is
then supplied to the selected translational scheme.

\section{Implemented Interval Order}

For each interval after initialization, the realized pipeline is:
\begin{enumerate}
    \item consume the latest source-agnostic control-state snapshot and any
          actual IMU increments published since the preceding Autopilot tick;
    \item if Guidance is due, advance its runtime state graph and hold the new
          acceleration/bank command, convert acceleration to body specific
          force, and advance the persistent Guidance command filter;
    \item if Autopilot is due, form the banked velocity-aligned attitude
          command and advance the Autopilot body-rate response;
    \item evaluate the environment at the Physics interval start;
    \item advance the Vehicle's body-rate and two internal specific-force
          response stages, then apply optional final limits;
    \item integrate $\quat_b^i$ with previous and current realized body rate;
    \item predict endpoint position and reevaluate endpoint gravity;
    \item form current inertial acceleration from final realized body specific
          force;
    \item integrate ECI velocity and position;
    \item emit ECEF truth with
          \cref{eq:inertial_fixed_position,eq:inertial_fixed_velocity}.
\end{enumerate}

When the launch-pad constraint is active,
\cref{eq:pad_eci_state,eq:pad_support_force} replaces the free plant update.
This is an explicit support condition, not a large control gain or a
post-integration state reset.

\begin{implbox}
The order above is part of the v1 numerical contract. In particular, no
controller integrates truth; attitude is updated before final body specific
force is rotated into ECI at the endpoint; and limits are applied before
either attitude or translation is integrated.
\end{implbox}
